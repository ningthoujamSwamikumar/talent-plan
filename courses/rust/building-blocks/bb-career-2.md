# Building Block: Behavioral Interviews and Remote Communication Skills

Technical skills get you the interview. Behavioral skills get you the offer.
Remote Rust positions especially value communication skills because everything
happens in writing — Slack, GitHub, design docs. This building block prepares
you for the non-coding parts of the hiring process.

## Readings

- [The STAR Method for Behavioral Interviews](https://www.themuse.com/advice/star-interview-method)
  — read and internalize this framework. Every behavioral answer uses it.
- [Gergely Orosz: What I Look for When Hiring Senior Engineers](https://blog.pragmaticengineer.com/what-a-good-senior-engineer-looks-like/)
  — understand what the other side of the table is evaluating.
- [GitLab's Guide to All-Remote](https://handbook.gitlab.com/handbook/company/culture/all-remote/guide/)
  — skim sections on communication, async work, and documentation. GitLab
  literally wrote the book on remote work.

## Key Concepts

**The STAR method — your answer framework:**

- **S**ituation: Set the scene in 1-2 sentences. What was the context?
- **T**ask: What was your specific responsibility?
- **A**ction: What did you do? Be specific about YOUR actions, not the team's.
- **R**esult: What happened? Quantify if possible.

**Preparing STAR stories from this course:**

You've done real engineering work in this course. Frame it professionally:

| Question | Story Source |
|----------|-------------|
| "Tell me about a difficult technical problem you solved" | Implementing Raft consensus (Phase 5) — leader election edge cases, log divergence |
| "Tell me about a time you had to make a design tradeoff" | Choosing between storage engines in Phase 1, or database schema decisions in Phase 2 |
| "How do you approach testing?" | Property-based testing and fuzzing in Phase 3 — finding bugs that unit tests missed |
| "Tell me about a time you improved performance" | Profiling and optimization in Phase 3 — finding the bottleneck, measuring the improvement |
| "How do you handle working on unfamiliar code?" | Contributing to open source in Phase 8 — reading unfamiliar codebase, understanding conventions |
| "Tell me about a project you're proud of" | Your capstone — end-to-end system design, implementation, deployment |
| "How do you communicate technical decisions?" | Design doc writing in Phase 9 — RFC process, async communication |

**Common behavioral questions for remote roles:**

1. "How do you manage your time working remotely?"
2. "How do you communicate when you're blocked?"
3. "Tell me about a disagreement with a teammate and how you resolved it."
4. "How do you stay productive without supervision?"
5. "How do you handle code review feedback you disagree with?"

**Red flags interviewers watch for:**

- Blaming others for failures
- Not being able to explain what YOU specifically did
- Vague answers without concrete details
- Not asking questions about the role and team
- Poor writing in follow-up emails (for remote roles, this matters a lot)

## Exercises

1. Write out 7 STAR stories using the table above. Each story should be 150-250
   words. Practice saying them out loud until you can deliver them in under 2
   minutes each.

2. For each story, prepare a follow-up: "What would you do differently?" — this
   question always comes next. Have a genuine answer that shows growth.

3. Practice a mock interview with a friend or recording yourself. Ask them to
   evaluate: Did you answer the actual question? Were you specific? Did you
   quantify the result?
